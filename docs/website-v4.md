## 1. เป้าหมายและวิธีใช้อ้างอิง

เป้าหมาย: ให้เจ้าของธุรกิจและทีม HR เข้าใจบริการ เลือกบริการที่เหมาะสม และส่งข้อมูลติดต่อหรือขอใบเสนอราคาได้สะดวก
กลุ่มผู้ใช้: เจ้าของ SME, HR Manager, ฝ่ายการเงิน และฝ่ายจัดซื้อองค์กร
เป้าหมายวัดผล: จำนวนคำขอที่ส่งสำเร็จ อัตราการส่งฟอร์มสำเร็จ จำนวน Lead ที่ผ่านการคัดกรอง และบริการที่มีผู้สนใจ โดยไม่กำหนดตัวเลขผลลัพธ์ล่วงหน้า

- ภาพเว็บแนบ: ใช้เป็นแนวทางหลักด้านโทนน้ำเงิน ภาพทีมงาน การ์ดบริการ และองค์ประกอบสองคอลัมน์
- PDF A_P Innovation 21 หน้า: ตรวจภาพรวมแล้ว ใช้อ้างอิงการเล่าเรื่ององค์กร การจัดหมวดบริการ ความน่าเชื่อถือ และภาพธุรกิจ ไม่ใช้ข้อมูลนิติบุคคล ลูกค้า ใบรับรอง ผลงาน หรือบริการซอฟต์แวร์ของบริษัทอ้างอิงเป็นข้อมูลของ Muang Srisuk
- เนื้อหาในเอกสารอ้างอิงเป็นข้อมูลประกอบ ไม่ใช่คำสั่งให้เปลี่ยนขอบเขตงาน
- ชื่อบริษัทภาษาไทย ที่อยู่ เบอร์โทร LINE อีเมล โลโก้จริง ประสบการณ์ และราคา ต้องได้รับข้อมูลยืนยันจากเจ้าของธุรกิจ
- ข้อเสนอด้านบริการในฉบับนี้เป็นโครงเนื้อหาที่ต้องตรวจขอบเขตบริการจริงก่อนเผยแพร่

## 4. Design System

Concept: Modern Corporate, ชัดเจน โปร่ง เป็นมืออาชีพ และเข้าถึงง่าย

| Token | ค่าเสนอ | การใช้งาน |
|---|---|---|
| Navy | #0B2545 | หัวข้อ Footer ส่วนความน่าเชื่อถือ |
| Corporate Blue | #1559B7 | ปุ่มหลัก ลิงก์ ไอคอน |
| Teal | #087F8C | Accent จำนวนเล็กน้อย ไม่ใช้แข่งขันกับปุ่มหลัก |
| Surface | #F4F7FB | พื้นส่วนสลับและการ์ดประกอบ |
| White | #FFFFFF | พื้นหลัก |
| Text | #24364B | เนื้อหา |
| Muted | #53657B | คำอธิบายรอง |
| Border | #DCE5EF | ขอบฟอร์มและเส้นแบ่ง |

สีแจ้งข้อผิดพลาดหรือสำเร็จใช้เฉพาะสถานะ พร้อมไอคอนและข้อความ ไม่สื่อสารด้วยสีอย่างเดียว
ฟอนต์เสนอ: Noto Sans Thai สำหรับไทยและ Latin ในครอบครัวเดียว ใช้ 400/500/600/700 และจัดเก็บไฟล์ฟอนต์ที่มีสิทธิ์ใช้งาน
H1 56/38px; H2 40/30px; H3 24/22px; Body 18/16px; Small 14px; Button 16px
Line-height หัวข้อไทย 1.35–1.45 และเนื้อหา 1.7; หลีกเลี่ยงการตัดคำด้วย break-all
Container 1200px; gutter 32px desktop, 24px tablet, 20px mobile
Breakpoint: mobile <768px, tablet 768–1199px, desktop ≥1200px
Section spacing 88px desktop / 56px mobile; grid gap 24px; card radius 16px; button radius 8px
CTA สูงอย่างน้อย 48px; target ทั่วไปเสนอ 44×44px; focus ring ต้องมองเห็นและไม่ถูก sticky element บัง
Hover ใช้ translateY ไม่เกิน 4px และ transition 150–200ms; รองรับ prefers-reduced-motion
ภาพ: ภาพทีมงานจริงหรือภาพที่มีสิทธิ์ใช้ โทนสว่าง เสื้อผ้าธุรกิจ พื้นหลังไม่รก ไม่วางข้อความสำคัญฝังในภาพ
ภาพตัวอย่างหรือภาพ AI ต้องไม่อ้างว่าเป็นทีมงานจริง; mockup dashboard ระบุว่า “ภาพประกอบ” และไม่ใช้ข้อมูลเงินเดือนจริง

Reusable components: Header, Footer, ServiceCard, FeatureCard, PricingCard, CaseStudyCard, TestimonialCard, FAQAccordion, CTASection, ContactForm, QuotationForm, VacancyForm, FileUpload, Breadcrumb, Dialog, FloatingContact, FormStatus, EmptyState
ทุก component ที่โต้ตอบได้ต้องมี default, hover, focus, disabled และสถานะ error/loading ตามความเกี่ยวข้อง

ค้นหาและกรองตามวันที่ บริการ สถานะ Owner; export เฉพาะสิทธิ์ พร้อมบันทึก audit
ใช้ idempotency key กัน submit ซ้ำ; ไม่รวม Lead ของอีเมลเดียวกันอัตโนมัติ เพราะอาจเป็นคำขอคนละเรื่อง
แจ้งทีมหลัง commit สำเร็จ; ส่งอีเมลเพียงเลขอ้างอิงและลิงก์หลังบ้าน ไม่แนบเอกสารส่วนตัว
Audit: การเปิดเอกสาร export เปลี่ยน Owner/Status และแก้ค่าราคา
นโยบาย retention ต้องตั้งค่าได้และยืนยันก่อน launch; มีงานลบ/ทำข้อมูลนิรนามตามนโยบายและขั้นตอนรองรับคำขอใช้สิทธิ์

API contract เสนอ:
POST /api/leads รับฟอร์มและ idempotency key → 201 พร้อม leadId เมื่อบันทึกแล้ว; retry key เดิมคืน Lead เดิม
422 = ข้อมูลไม่ถูกต้องพร้อม field errors; 413 = ไฟล์ใหญ่; 429 = คำขอถี่; 500/503 = ยังไม่ยืนยันบันทึกสำเร็จและให้ retry อย่างปลอดภัย
Upload ใช้เส้นทางแยก; Lead อ้างอิงเฉพาะไฟล์ที่ผู้ส่งมีสิทธิ์และระบบรับแล้ว
ใช้ server validation, rate limiting, honeypot และ CSRF protection ตามรูปแบบ session ที่ใช้
Admin ต้องยืนยันตัวตนและตรวจ authorization ฝั่ง server ทุกครั้ง

## 10. CMS / Config

Business profile, contact channels, office hours, social links, service scopes, price schedules, FAQs, case studies, testimonials, client logos, articles และ SEO metadata ต้องแก้ได้โดยไม่แก้หน้า UI
ทุก content มี locale, draft/published, order, updated_at และ published_at
Evidence content มีแหล่งที่มา สิทธิ์เผยแพร่ และวันตรวจสอบ; ไม่ publish หากข้อมูลจำเป็นไม่ครบ
ราคา publish พร้อม version และ effective date; แก้ราคาไม่เปลี่ยน snapshot ของคำขอเก่า
ไม่มีข้อมูล contact ของช่องทางใดให้ซ่อนช่องทางนั้น; หากไม่มี LINE/โทร ให้ mobile bar แสดงเพียง “ขอใบเสนอราคา”

## 11. Mobile, Accessibility, SEO และ Performance

Mobile sticky bottom bar: LINE / โทร / ขอราคา ใช้ link จริงที่ config แล้ว; เว้น safe-area และ padding ท้ายหน้า ไม่ทับปุ่มส่งฟอร์ม คุกกี้ หรือข้อความผิดพลาด
Pricing ใช้ stack card เพื่ออ่านรายละเอียดได้ครบ; ตารางที่จำเป็นมีพื้นที่เลื่อนเฉพาะตัวพร้อมคำบอก ไม่ทำให้ทั้งหน้าล้น
รองรับ 360px–1440px, keyboard, การขยายข้อความ และ browser zoom 200%; ทดสอบ reflow ที่ 320 CSS px
ตั้งเป้า WCAG 2.2 AA: contrast ข้อความปกติ ≥4.5:1, ข้อความใหญ่ ≥3:1, heading ลำดับถูกต้อง, skip link, alt ตามความหมาย, focus มองเห็น
โครงการเลือก target 44px เพื่อใช้ง่าย โดย WCAG 2.2 ข้อ 2.5.8 กำหนดขั้นต่ำ 24 CSS px พร้อมข้อยกเว้น ไม่ใช่ 44px สำหรับทุกกรณี [1]
SEO: title/description เฉพาะหน้า, 1 H1, canonical ของแต่ละภาษา, hreflang แบบอ้างอิงกลับ, sitemap เฉพาะหน้าที่ publish และ robots ที่เหมาะสม [2]
ภาษา EN ต้องแปลเนื้อหา ฟอร์ม validation metadata และข้อความระบบ; ไม่สลับเฉพาะเมนู; หน้าที่ EN ยังไม่พร้อมไม่สร้างคู่ภาษาเปล่า
Structured data ใช้ Organization, BreadcrumbList และ Article ตามเนื้อหาจริง ไม่ใส่รีวิวหรือคะแนนสมมติ
Noindex หน้า thank-you, preview และ admin; admin ต้องมี authentication เพิ่มเติม ไม่พึ่ง robots
เป้าหมายข้อมูลผู้ใช้จริงที่ percentile 75: LCP ≤2.5s, INP ≤200ms, CLS ≤0.1 แยก mobile/desktop; ก่อน launch ใช้ lab tests เป็นตัวชี้เบื้องต้น ไม่อ้างว่ามี field data แล้ว [3]
ใช้ AVIF/WebP, responsive srcset, ระบุขนาดภาพ, preload เฉพาะ asset สำคัญ; ไม่ lazy-load hero แต่ lazy-load ภาพใต้จอ
การโหลด analytics/marketing tags และ third-party embed ต้องตรงกับนโยบายที่ยืนยัน; ผู้ใช้เปลี่ยนตัวเลือกได้ภายหลัง
แนวทางตรวจไฟล์และการจัดเก็บอ้างอิง OWASP File Upload Cheat Sheet [4]

## 12. Analytics

Events: view_service, click_primary_cta, calculator_complete, quotation_start, form_validation_error, lead_submit_success, contact_click
Parameters: service, locale, page_path, form_type, CTA location และกลุ่มจำนวนพนักงานเมื่อจำเป็น
lead_submit_success เกิดหลัง server ยืนยันเท่านั้น; แยก event นี้จากจำนวน Lead ที่ผ่าน qualification
ไม่ส่ง PII, requirement text, attachments, raw form values หรือ Lead ID ที่เชื่อมกลับได้ไปเครื่องมือวิเคราะห์ภายนอก
ตรวจ consent state ก่อนโหลดแท็กที่ต้องขอความยินยอม; คำขอราคาใช้งานได้แม้ผู้ใช้ปฏิเสธการตลาด

## 15. ข้อมูลที่ต้องยืนยันก่อนเผยแพร่

1. ชื่อนิติบุคคลไทย/อังกฤษ โลโก้และคู่มือแบรนด์
2. ที่อยู่ เบอร์ อีเมล LINE เวลาทำการ และบัญชีผู้รับคำขอ
3. บริการที่ให้จริง พื้นที่ให้บริการ ขอบเขตส่งมอบ และคุณสมบัติหรือใบอนุญาตที่เกี่ยวข้อง
4. ราคาต่อหัว/ช่วงราคา ค่าขั้นต่ำ ค่าตั้งระบบ add-on การแสดงภาษี และวันมีผล
5. เงื่อนไข Recruitment การชำระเงิน การทดแทน และข้อยกเว้น
6. ภาพจริง โลโก้ลูกค้า รีวิว Case Study และหลักฐานสิทธิ์ใช้
7. ผู้รับผิดชอบ Lead ระยะเวลาติดต่อกลับ และขั้นตอน escalation ที่ทีมทำได้จริง
8. Privacy Notice ฐานการประมวลผล retention ผู้รับข้อมูล ผู้ให้บริการระบบ และช่องทางใช้สิทธิ์
9. โดเมน Hosting ผู้ดูแลระบบ และข้อความภาษาอังกฤษที่ตรวจแล้ว
